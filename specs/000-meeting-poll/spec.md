## 1. 배경 / 문제 정의
Meeet은 여러 사람이 참여하는 미팅 하나의 시간을 빠르게 정하기 위한 일회성 도구다(When2meet식).
회원가입 없이 누구나 바로 미팅 폴을 만들 수 있고, 생성된 폴마다 고유한 공개 링크가 발급된다.

폴 생성자는 **캘린더에서 후보 날짜 여러 개를 고르고, 하루 시간 범위(예: 오전 9시~오후 5시)를
지정**한다. 서버는 이 [날짜 × 시간 범위]를 **30분 격자**로 펼쳐 후보 시간 칸들을 만든다.
참가자는 링크로 들어와 이름을 입력하고, **격자에서 자신이 가능한 시간 칸을 클릭·드래그로 칠한다**.
모두의 응답은 칸마다 가능 인원이 진해지는 **히트맵**으로 한눈에 모여, 가장 많은 사람이 가능한
시간을 빠르게 찾을 수 있다. 특정 칸을 가리키거나 클릭하면 그 시간에 가능한 사람과 불가능한
사람의 명단이 함께 보여, 시간 결정을 눈으로 판단할 수 있다. (시스템이 하나의 시간을 "확정"해
폴을 마감하는 기능은 두지 않는다 — 결정은 사람들이 히트맵을 보고 오프라인으로 내린다.)

이 도구에는 사이트 차원의 계정/로그인 개념이 없다. 폴을 만든 사람도, 폴에 참여하는
사람도 별도 회원가입을 하지 않는다 — "참여하려면 이름을 입력한다"가 유일한 등록 절차다.
폴의 공개 링크(토큰)를 아는 것 자체가 그 폴에 대한 접근/참여 권한이다.
(Calendly처럼 폴 생성자가 반복되는 가용 시간을 영구 등록해두는 모델이 아니다 — 그 모델은 비목표.)

## 2. 목표 (Goals)
- 누구나 로그인 없이, 캘린더에서 후보 날짜 여러 개 + 하루 시간 범위를 골라 미팅 폴을 즉시 만들 수 있다.
- 서버는 [선택 날짜 × 시간 범위]를 30분 격자 칸으로 펼쳐 저장한다.
- 폴 생성 시 추측 불가능한 토큰 기반의 공개 링크가 발급되어 바로 공유할 수 있다.
- 참가자는 링크로 들어와 이름을 입력하고, 격자에서 가능한 시간 칸을 클릭·드래그로 칠해 응답한다.
- 누구나 폴 페이지에서 칸별 가능 인원을 히트맵으로 보고, 특정 칸을 가리키거나 클릭하면 그 칸에 가능한 사람과 불가능한 사람의 명단을 확인할 수 있다.

## 3. 비목표 (Non-Goals)
- 사이트 차원의 회원가입/로그인, 사용자 계정, 비밀번호 — 폴 생성자와 참가자 모두 계정이 없다.
  (이하 "호스트"라는 표현은 쓰지 않고 "폴 생성자"로 통일한다.)
- 폴 생성자 전용 대시보드("내가 만든 폴 목록") — 계정이 없으므로 존재할 수 없다.
- 요일 반복 폴("매주 월/수/금") — MVP는 특정 날짜만 지원한다.
- 날짜만 고르는 올데이(시간 없는) 폴 — MVP는 하루 시간 범위 + 30분 격자를 항상 사용한다.
- 30분 외의 가변 격자 간격(15분/1시간 선택) — MVP는 30분 고정.
- 반복되는 주간 가용 시간 등록 (Calendly식 모델).
- 참가자 이메일/푸시 알림.
- 외부 캘린더 연동(Google Calendar 등).
- "가능 / 불가능 / 어쩌면" 같은 3단계 응답 — MVP는 가능/불가능 2단계만.
- 시스템 차원의 시간 "확정"/폴 마감 — 폴에는 열림/마감 상태 구분이 없다. 최종 시간 결정은 사람들이 히트맵과 칸별 명단을 보고 폴 밖에서 내린다.
- 폴 생성자가 직접 폴을 삭제/수정하는 기능 — 여전히 지원하지 않는다. 단 폴은 후보 기간이 지나면 **자동으로 만료·삭제**된다(FR-13). 이는 사용자 조작이 아니라 시스템의 수명 관리다.
- 계정/이메일 기반의 참가자 본인 인증 — 참가자 식별은 브라우저 localStorage의 익명 편집 토큰으로만 한다. 따라서 다른 기기/브라우저/시크릿창에서는 같은 참가자로 수정할 수 없고 새 응답이 된다(계정이 없는 모델의 본질적 한계, 수용).
- 폴 생성 후 날짜/시간 범위 변경, 사용자에 의한 폴 삭제 — MVP는 생성만 지원하고 수정/수동 삭제는 지원하지 않는다(자동 만료는 FR-13으로 별도 지원).

## 4. 사용자 시나리오 (User Stories)
- P1: As a 폴 생성자, I want to 가입 없이 캘린더에서 후보 날짜들과 하루 시간 범위를 골라 폴을 만들고, so that 곧바로 참가자들에게 투표를 요청할 수 있다.
- P1: As a 폴 생성자, I want to 생성 직후 공개 링크를 받고, so that 참가자에게 바로 공유할 수 있다.
- P1: As a 참가자, I want to 링크에 접속해 이름만 입력하고 격자에서 가능한 시간을 드래그로 칠하고, so that 별도 가입 없이 빠르게 참여할 수 있다.
- P1: As a 링크를 가진 사람, I want to 칸별 가능 인원을 히트맵으로 보고 특정 칸을 가리키거나 클릭해 그 칸의 가능자·불가능자 명단을 확인하고, so that 가장 많은 사람이 가능한 시간과 누가 빠지는지를 쉽게 파악할 수 있다.
- P2: As a 참가자, I want to 이미 제출한 내 응답을 나중에 다시 와서 수정하고, so that 일정이 바뀌었을 때 반영할 수 있다.
- P2: As a 참가자, I want to 격자 전체 또는 특정 날짜 전체를 한 번에 선택/해제하고, so that 대부분의 시간이 가능하거나 특정 날짜가 통째로 가능/불가능할 때 칸을 일일이 드래그하지 않아도 된다.
- P2: As a 모바일 참가자, I want to 칸을 길게 눌러 드래그로 여러 칸을 이어서 칠하고, so that 연속된 시간대를 표시할 때 칸마다 따로 탭하지 않아도 된다.

## 5. 기능 요구사항 (Functional Requirements)
- FR-1: 누구나 로그인/회원가입 없이 미팅 폴을 생성할 수 있다.
- FR-2: 폴 생성 입력은 제목(필수), 설명(선택), 후보 날짜 목록(1개 이상), 하루 시간 범위(시작 시각·종료 시각, 종료 > 시작)로 구성된다.
- FR-3: 서버는 [후보 날짜 × 시간 범위]를 30분 격자로 펼쳐 후보 시간 칸(슬롯)들을 생성·저장한다. 각 칸은 30분 길이다. 과거 날짜는 후보로 넣을 수 없다(과거 날짜 거부). 단 오늘 날짜를 고른 경우 이미 지난 시간대 칸이 일부 남을 수 있는데, MVP에서는 이를 별도로 제거하지 않고 수용한다(폴에서 지난 칸에 가능 표시는 무의미할 뿐 해롭지 않음).
- FR-4: 폴 생성 시 추측 불가능한 공개 토큰이 발급된다. 폴 조회와 참가자 응답을 포함한 모든 동작은 이 토큰을 아는 것만으로 가능하다 — 별도의 생성자 권한 구분은 없다.
- FR-5: 공개 폴 페이지는 폴 제목, 설명, 날짜×시간 격자, 현재까지의 참여 현황(칸별 가능 인원 히트맵)을 누구나 볼 수 있다.
- FR-6: 참가자는 이름을 입력하고, 격자에서 가능한 칸을 클릭·드래그로 선택(토글)한 뒤 응답을 제출할 수 있다. 드래그는 누르기 시작한 칸의 반대 상태(목표 상태)로, 같은 날짜 컬럼 안에서 **시작 칸부터 현재 포인터가 있는 칸까지의 연속 구간**을 칠한다 — 포인터가 거꾸로 돌아와 구간이 줄어들면 구간 밖으로 빠진 칸은 드래그 전 상태로 되돌아가고, 포인터가 빠르게 움직여 중간 칸을 건너뛰어도 구간 안의 칸은 모두 칠해진다. 드래그 중 포인터가 격자의 보이는 영역 위/아래 가장자리에 가까워지거나 그 밖으로 나가면 FR-16과 같은 규칙으로 격자(필요하면 페이지)가 자동 스크롤되며 이어 칠해진다. 마우스 드래그는 포인터가 격자 밖으로 나가도 버튼을 놓을 때까지 이어진다. 칠한 칸 = "가능", 칠하지 않은 칸 = "불가능"(2단계). 폴에는 마감 상태가 없으므로 응답은 언제든 받는다.
- FR-7: 참가자는 최초 응답 제출 시 서버로부터 익명 편집 토큰을 발급받아 브라우저(localStorage)에 저장한다. 같은 브라우저에서 재제출하면 이 토큰으로 본인을 식별해 기존 응답(이름·선택)을 갱신한다 — 이름을 바꿔도 같은 참가자로 유지된다. 토큰이 없는 제출은 항상 새 참가자를 만든다. (이름은 식별자가 아니므로 같은 폴에 같은 이름이 여러 명 존재할 수 있다.)
- FR-7a: 편집 토큰을 가진 참가자가 폴 페이지를 다시 열면 자신의 이전 응답(이름과 선택한 칸)이 격자에 자동으로 채워진다(프리필).
- FR-8: 폴 페이지는 칸별 가능 인원을 집계해 히트맵(가능 인원이 많을수록 진한 색)으로 보여준다. 특정 칸을 마우스로 가리키거나 클릭하면 그 칸에 **가능한 참가자 명단과 불가능한(응답했지만 그 칸을 칠하지 않은) 참가자 명단**을 함께 보여준다. 클릭한 칸은 고정되어(pin) hover가 없는 터치 기기에서도 상세를 읽을 수 있다.
- FR-9: (제거됨 — 시간 확정 기능 삭제, 2026-07-01 개정)
- FR-10: (제거됨 — 시간 확정 기능 삭제, 2026-07-01 개정)
- FR-11: 모든 사용자 입력(폴 생성, 참가자 응답)은 Zod 스키마로 검증한다.
- FR-13: 폴은 **마지막 후보 날짜의 다음날 0시로부터 7일 뒤 0시(생성자 타임존 기준)**에 만료된다 — 후보 기간이 끝난 뒤에도 일주일 동안은 결과를 다시 볼 수 있도록 하는 유예 기간이다(예: 마지막 후보 날짜 10/17 → 10/25 0시 만료). 만료 시각(`expiresAt`)은 생성 시점에 UTC로 계산·저장한다. 만료된 폴은 즉시 조회 불가(404)로 취급하고(응답 제출도 404), 스케줄러(Cron)가 주기적으로 만료된 폴을 실제로 삭제한다(자식 슬롯·참가자·응답은 FK cascade로 함께 삭제). 이로써 일회성 도구의 데이터가 무기한 남지 않는다.
- FR-12: 후보 시간 칸·참여 현황은 서버에 UTC로 저장하고, 클라이언트(공개 폴 페이지)에서는 각 사용자의 브라우저 타임존으로 변환해 표시한다. 격자의 날짜 행/시간 열은 뷰어의 브라우저 타임존 기준으로 재구성한다 — 생성 시점의 칸 경계(생성자 타임존 기준 30분)는 UTC로 고정되지만, 표시 시 행/열 배치는 뷰어마다 달라질 수 있다(§6 데이터 모델 노트, §8 타임존 참고).
- FR-14: 참가자의 응답 입력 격자에는 "전체 선택" 토글이 있다. 격자 내 칸이 하나라도 선택되어 있지 않으면 누르는 즉시 모든 칸을 선택 상태로 채우고, 이미 모든 칸이 선택되어 있으면 눌렀을 때 전부 해제한다(indeterminate 토글 — 항상 "전부 채워진 상태"와 "전부 빈 상태" 중 반대쪽으로 전환).
- FR-15: 참가자의 응답 입력 격자에서 각 날짜 컬럼의 헤더(날짜 라벨)를 클릭하면 그 날짜 컬럼에 한해 FR-14와 동일한 규칙(하나라도 비었으면 전체 채움, 전부 찼으면 전체 해제)으로 토글한다. FR-14/15는 이름 미입력 등으로 격자 자체가 비활성화된 상태(FR-6의 입력 비활성 조건)에서는 함께 비활성화된다. 두 토글 모두 서버 요청 없이 클라이언트의 로컬 선택 상태만 바꾸며, 실제 반영은 기존 FR-6의 "응답 제출"로 이루어진다.
- FR-16: 터치 기기에서도 격자를 드래그해 여러 칸을 이어서 칠할 수 있다. 칸을 일정 시간(약 300ms) 누르고 있으면 **칠하기 모드**로 진입하고, 그 상태에서 손가락을 움직이면 지나가는 칸이 FR-6의 드래그와 동일한 규칙(처음 칸의 반대 상태로, 같은 날짜 컬럼 안의 시작 칸~현재 칸 구간)으로 칠해진다. 손을 떼면 모드가 끝난다. 누른 직후 손가락이 임계치 이상 움직이면 칠하기 모드로 들어가지 않고 기존처럼 격자 스크롤로 동작한다 — 즉 "길게 누름"과 "쓸어넘김"으로 칠하기와 스크롤을 가른다. 짧은 탭으로 한 칸을 토글하는 기존 동작(FR-6)은 그대로 유지되고, 마우스·펜 입력의 동작도 바뀌지 않는다. 칠하기 모드는 격자가 비활성화된 상태(FR-6의 입력 비활성 조건)에서는 진입하지 않는다. 사용자가 조작법을 알 수 있도록 응답 입력 격자 위에 "길게 눌러 드래그하면 여러 칸을 칠할 수 있어요" 안내 문구를 **터치 기기(거친 포인터)에서만** 표시한다 — 마우스 환경에서는 보이지 않는다. 칠하기 모드 중 손가락이 격자의 보이는 영역 위/아래 가장자리에 가까워지거나 그 밖으로 나가면 격자가 그 방향으로 **자동 스크롤**되고, 스크롤로 손가락 아래에 들어온 칸도 같은 규칙으로 이어 칠해진다(가장자리에 가까울수록 빠르게). 격자를 더 스크롤할 수 없는데 격자가 화면 밖으로 이어져 있으면 페이지를 스크롤한다. 덕분에 한 번의 제스처로 화면에 가려진 칸까지 칠할 수 있다.
- FR-17: 응답 입력(이름·선택한 칸)이 마지막으로 저장된 응답과 다르면 "제출하지 않은 변경이 있어요"를 응답 제출 버튼 옆에 표시하고, 모바일의 "내 가능 시간" 탭에도 표시(점)를 단다. 저장된 응답이 없는 참가자(첫 응답 중)에게는 표시하지 않는다 — 제출 전인 것이 당연하므로 안내가 소음이 된다. 판단은 "수정했는지"가 아니라 "저장된 값과 다른지"로 하므로, 고쳤다가 원래대로 되돌리면 표시가 사라진다. 탭을 오가도 제출하지 않은 입력은 버리지 않는다.

- 격자는 `PollSlot` 칸들의 집합으로 표현된다. 별도의 "날짜 목록"이나 "시간 범위" 컬럼은
  두지 않고, 슬롯들에서 파생한다. 단 날짜 행/시간 열로의 분해는 **각 뷰어의 브라우저 타임존
  기준**으로 한다(FR-12) — 같은 폴이라도 뷰어 타임존이 다르면 행/열 배치가 달라질 수 있다
  (자정 부근 칸이 다른 날짜로 넘어가는 등). 격자 간격(30분)은 코드 상수다.
- User 테이블은 없다 — 이 프로젝트에는 인증 대상이 되는 계정 엔티티가 존재하지 않는다.

## 7. API / 인터페이스 개요

페이지 (App Router):
- `GET /` — 폴 생성 페이지. 캘린더로 후보 날짜 선택 + 하루 시간 범위 지정 폼이 여기 있다 (서비스의 진입점).
- 폴 생성 성공 시 별도 완료 화면 없이 `/p/{token}`으로 즉시 이동한다. 공개 링크 공유는
  폴 페이지 상단의 생성자 전용 배너(링크 + 복사, 닫기 가능)가 담당한다. 생성자 식별은
  같은 탭의 sessionStorage 플래그로 하며, 링크로 들어온 참가자에게는 배너가 보이지 않는다
  (완료 화면 → 리다이렉트+배너로 변경, 2026-07-04).
- `GET /p/{token}` — 공개 폴 페이지. 격자 조회, 참가자 응답(드래그 칠하기), 히트맵, 칸별 가능/불가능 명단 조회를 모두 이 페이지에서 수행한다 (인증 불필요).

API:
- `POST /api/polls` — 미팅 폴 생성. 입력 `{ title, description?, dates[], startTime, endTime, timeZone }`를
  받아 30분 격자 슬롯으로 펼쳐 저장하고, 발급된 `publicToken`을 반환한다 (인증 불필요).
  `timeZone`(IANA 문자열)은 `dates`/`startTime`/`endTime`을 UTC로 변환하는 기준이므로 필수다.
- `POST /api/polls/{token}/responses` — 참가자 응답 제출/수정. 입력 `{ name, availableSlotIds[], editToken? }`. editToken이 있고 그 폴의 참가자를 가리키면 해당 응답을 갱신, 없으면 새 참가자 생성. 응답으로 `{ editToken, participantId }`를 반환해 클라이언트가 저장한다 (인증 불필요).
- 칸별 가능/불가능 명단은 별도 API 없이, 폴 페이지가 이미 받은 참가자·가능표시 데이터로 클라이언트에서 파생한다(FR-8).
- `GET /api/cron/cleanup` — 만료된 폴(`expiresAt <= now`)을 삭제하는 스케줄러 전용 엔드포인트(FR-13). `CRON_SECRET` 환경변수가 설정되면 `Authorization: Bearer <secret>` 헤더가 있어야 실행된다(Vercel Cron 규약). 스케줄은 `vercel.json`의 crons로 매일 실행한다.

## 8. 엣지 케이스 & 에러 처리
- 후보 날짜가 0개이거나 시간 범위가 비정상(종료 ≤ 시작)인 생성 요청은 Zod 단계에서 거부한다.
- 시간 범위가 30분 단위로 나누어떨어지지 않으면(예: 9:00~9:20) 거부하거나 30분 경계로 내림 처리한다 — 거부로 단순화한다.
- 격자가 지나치게 커지는 입력(날짜를 너무 많이 고르거나 시간 범위가 과도하게 넓음)은 칸 수 상한(MVP: 날짜 ≤ 31, 총 칸 ≤ 1000)으로 거부한다(plan §7 격자 폭증 방어).
- 과거 날짜를 후보로 넣는 생성 요청은 거부한다.
- 존재하지 않는 publicToken으로 접근하면 404를 반환한다.
- 만료된(`expiresAt <= now`) 폴은 아직 물리적으로 삭제되기 전이라도 조회·응답 모두 404로 취급한다(FR-13). 만료된 폴 페이지를 연 브라우저는 저장돼 있던 편집 토큰(localStorage)을 정리한다.
- 응답 제출 시 `availableSlotIds`에 이 폴 소속이 아닌 칸이 섞이면 400을 반환한다.
- 제출에 담긴 editToken이 다른 폴의 참가자를 가리키거나 존재하지 않으면, 그 토큰은 무시하고 새 참가자를 만든다(에러 아님). 남의 편집 토큰을 알면 그 응답을 수정할 수 있으나, 토큰은 충분한 엔트로피의 랜덤값이라 추측 불가하다(수용, FR-7).
- **타임존**: 슬롯은 UTC로 저장한다. 격자는 폴 생성자의 타임존 기준 30분 경계로 만들어지고, 다른 타임존의 참가자에게는 변환된 로컬 시각으로 라벨을 표시한다(FR-12). 30분 단위가 아닌 타임존(예: UTC+5:30)에서는 라벨이 :00/:30이 아닌 경계로 보일 수 있으나 칸 자체는 동일하게 유지된다(수용).
- 전체 선택/날짜별 전체 선택(FR-14/15)은 이름 미입력 등으로 격자가 비활성화된 동안에는 버튼 자체도 비활성화해 클릭이 아무 효과가 없도록 한다.
- 날짜별 전체 선택은 헤더를 클릭한 그 날짜 컬럼의 칸에만 영향을 주고 다른 날짜에는 영향을 주지 않는다.
- **터치 칠하기(FR-16)**: 롱프레스로 칠한 뒤 손을 떼면 브라우저가 click 이벤트를 이어서 발생시키는데, 그대로 두면 마지막 칸이 한 번 더 뒤집힌다 — 칠하기 모드를 거친 제스처의 click은 무시한다.
- 칠하기 모드에 들어가면 격자의 네이티브 스크롤을 막는다(막지 않으면 칠하는 동안 격자가 따라 움직여 엉뚱한 칸이 칠해진다). 모드가 끝나면 즉시 복구한다.
- 칠하기 모드 중 손가락이 격자 밖으로 나가도 모드는 유지된다 — 위/아래로 나가면 자동 스크롤이 최대 속도로 계속되고, 칸이 아닌 곳(시간 라벨, 날짜 헤더, 격자 옆 여백 등) 위에서는 아무것도 칠하지 않는다. 손을 떼거나 전화·알림 등으로 제스처가 취소되면(pointercancel) 모드와 자동 스크롤을 즉시 종료하고 스크롤을 복구한다. 그때까지 칠해진 칸은 되돌리지 않는다.
- 칠하기 모드를 거치지 않은 다음 짧은 탭은 항상 정상적으로 한 칸을 토글해야 한다 — 직전 제스처의 click 무시 처리가 다음 탭으로 새어 나가면 안 된다(드래그 후에는 브라우저가 click을 보내지 않는 경우가 많다).
- 길게 누르는 동안 OS의 길게 누르기 동작(Android 컨텍스트 메뉴, iOS 콜아웃·텍스트 선택)이 끼어들면 안 된다.
- 칠하기 모드 진입 시 진동 피드백을 주되, 지원하지 않는 기기·브라우저에서는 조용히 건너뛴다(기능 자체는 동일하게 동작해야 한다).
